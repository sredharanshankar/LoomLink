# LoomLink — Engineering Contract (single source of truth)

> Every agent (Claude Code or Codex) and every human on the team MUST read this file before writing code.
> If code and this contract disagree, the contract wins. Changes follow §13 (contract change process).

Companion files: `docs/RBAC.md` (permissions), `docs/SEED.md` (demo data), `docs/OWNERSHIP.md` (who may edit what), `docs/CONCEPT.md` (product idea).

---

## 0. Golden rules

1. **Stay in your lane.** Only edit paths you own (see `docs/OWNERSHIP.md`). Need something from another lane? Use the interface in §8/§9 or raise a contract change (§13).
2. **One writer per table.** Every table has exactly one owning module that writes to it (§4). Others read only.
3. **Integers for money and quantities.** Money in **paise**, yarn in **grams**, fabric length in **centimetres**, durations in **minutes**. Never floats for these. Convert only at the UI edge.
4. **Time from one clock.** Backend code calls `app.core.time.now()` — never `datetime.now()` / `datetime.utcnow()`. Frontend uses server timestamps. Store UTC `timestamptz`; display in `Asia/Kolkata`.
5. **Scans never write.** Resolving a QR returns data and allowed actions. Only an authenticated, validated action call changes state.
6. **History is append-only.** Corrections are new rows (reversal/adjustment), never edits to stock movements, inspections, payments or events.
7. **Every mutation emits a domain event** through `app.core.events.publish()` inside the same DB transaction (§7).
8. **Every endpoint enforces permissions server-side** with `require_permission()` (§6, `docs/RBAC.md`). UI hiding is cosmetic only.
9. **No secrets in code.** Everything configurable comes from environment variables (§11).
10. **Honest labels.** Anything simulated or estimated is labelled as such in API responses (`"is_estimate": true`, `"source": "simulator"`) and in the UI.

## 3. Conventions

### 3.1 Units (integers only)

| Quantity | Stored as | Column suffix | UI display |
|---|---|---|---|
| Money | paise (BIGINT) | `_paise` | `₹1,23,456.00` via `Intl.NumberFormat('en-IN')` |
| Yarn weight | grams (BIGINT) | `_g` | kg with 1–3 decimals |
| Fabric length | centimetres (BIGINT) | `_cm` | metres with up to 2 decimals |
| Durations | minutes (INT) | `_minutes` | `3 h 20 m` |
| Rates | paise per unit | `_paise_per_kg`, `_paise_per_m`, `_paise_per_hour` | `₹220/kg` |
| Percent | basis points (INT) | `_bp` | 500 bp = 5% |
| Speed | unit per hour (INT) | `_per_hour` | `20 m/h`, `12 kg/h` |

Jobs carry a generic `qty` with a `unit` of `cm` (weaving, dyeing, finishing) or `g` (spinning).
Helper modules: `backend/app/core/units.py` and `frontend/src/lib/format.ts` (both created in Prompt 0).

### 3.2 Time
- DB: `timestamptz` (UTC). Dates that are business days (attendance date, payroll month, invoice date) are `date` in **mill local time** (`Asia/Kolkata`).
- `app.core.time.now()` returns aware UTC datetime; honours `DEMO_CLOCK_START` (see §11) so the demo mill can run "frozen" at a chosen moment that then advances in real time.
- API: ISO 8601 with offset (`2026-10-12T11:20:00+05:30` or `Z`).
- Mill shifts (default): **A 06:00–14:00**, **B 14:00–22:00**, **C 22:00–06:00 (overtime only)**.
- Indian financial year runs **1 April – 31 March** (used for invoice numbering).

### 3.3 IDs and human codes
- Primary keys: UUID v4 (`id`). Never shown to users.
- Every user-facing entity has a unique human `code`. Generated by `app.core.ids.next_code()` using the `code_sequences` table (row lock, gap-tolerant).

| Entity | Format | Example |
|---|---|---|
| Supplier | `SUP-###` | SUP-001 |
| Buyer | `BUY-###` | BUY-003 |
| Worker | `EMP-###` | EMP-012 |
| Yarn type | `YT-<MAT>-<COUNT>-<COL>` | YT-COT-40S-BLU |
| Fabric type | `FAB-<SHORT>-<COL>` | FAB-POP-BLU |
| Yarn batch | `YB-YYMM-NN` | YB-2610-03 |
| Purchase order | `PO-YYMM-NN` | PO-2610-02 |
| Order | `ORD-###` (starts 101) | ORD-104 |
| Job | `JOB-<orderNo>-<SS>[-n]` SS ∈ SP, WV, DY, FN | JOB-104-WV, JOB-104-WV-2 |
| Machine | manual: `SP-##`, `WV-##`, `DY-##`, `FN-##` | WV-02 |
| Roll | `ROLL-<orderNo>-NN` | ROLL-104-07 |
| Dispatch | `DSP-YYMM-NN` | DSP-2610-05 |
| Invoice | `INV-<FY>-####` FY = 2 + 2 digits | INV-2627-0001 |
| Payment received | `PAY-YYMM-NN` | PAY-2610-04 |
| Supplier bill | `SB-YYMM-NN` | SB-2610-01 |
| Ripple event | `RPL-YYMMDD-NN` | RPL-261012-01 |

### 3.4 QR payload
QR encodes a URL: `{PUBLIC_BASE_URL}/s/{code}` (e.g. `https://loomlink.local/s/WV-02`).
The app's scanner extracts the last path segment; the `/s/:code` web route lets a phone's native camera open the app too.
Labels exist for: yarn batches, machines, rolls, worker badges (EMP-codes, for attendance).
QR never contains prices, names or status.

### 3.5 API style
- Base path: `/api/v1`. JSON, `snake_case` keys. OpenAPI at `/api/v1/openapi.json`, docs at `/api/docs`.
- Lists: `GET ...?limit=50&offset=0&q=&sort=` → `{"items": [...], "total": 123}`. Max limit 200.
- Errors (always this shape):
  ```json
  { "error": { "code": "INSUFFICIENT_STOCK", "message": "Only 30.000 kg available in YB-2610-03", "details": { "available_g": 30000 } } }
  ```
  HTTP: 400 validation, 401 unauthenticated, 403 forbidden, 404 not found, 409 conflict/state, 422 schema, 429 rate limit.
- Standard error codes: `VALIDATION_ERROR, UNAUTHENTICATED, FORBIDDEN, NOT_FOUND, CONFLICT, INVALID_STATE, INSUFFICIENT_STOCK, MACHINE_BUSY, MACHINE_INCOMPATIBLE, NOT_ON_SHIFT, ROLL_NOT_PASSED, ROLL_ALREADY_DISPATCHED, ROLL_WRONG_ORDER, DUPLICATE_REFERENCE, OVER_ALLOCATION, STALE_SNAPSHOT, RATE_LIMITED, DEMO_ONLY`.
- Idempotency: mutating endpoints marked **[idem]** accept header `Idempotency-Key: <uuid>`; the server stores `(key, user_id, method+path) → status+body` for 24 h in `idempotency_keys` and replays the stored response on repeat.
- Every list/detail response that includes money is **role-filtered** (e.g., operators never receive `*_paise` wage fields). Filtering happens in the service/schema layer.
- Estimates carry `"is_estimate": true` and, where relevant, `"assumptions": {...}`.

### 3.6 Naming
Python: `snake_case`, modules singular per domain (`inventory.py`). TypeScript: `camelCase` vars, `PascalCase` components, files `PascalCase.tsx` for components, `kebab-case.ts` for utilities. API JSON stays `snake_case` in TS too (generated types) — do not re-map keys.

## 5. Enums (Postgres native enums; Python `StrEnum`; TS string unions — identical values)

```
role:             owner, manager, storekeeper, operator, qc_inspector, dispatch, accounts, buyer
language:         en, hi, te, ta
stage:            spinning, weaving, dyeing, finishing
unit:             cm, g
machine_status:   idle, running, breakdown, maintenance, changeover, offline
job_status:       planned, ready, running, paused, blocked, done, cancelled
order_status:     draft, confirmed, in_production, qc, ready, partly_dispatched, dispatched, closed, cancelled
order_priority:   normal, high, rush
roll_status:      pending_qc, passed, rework, rejected, dispatched
qc_decision:      passed, rework, rejected
defect_severity:  minor, major, critical
dispatch_status:  draft, loading, dispatched, in_transit, delivered, cancelled
invoice_status:   issued, partly_paid, paid, cancelled
movement_kind:    receipt, issue, return, adjustment, scrap
attendance_status: present, absent, half_day, leave, holiday
wage_type:        daily, hourly, monthly, piece
health:           green, amber, red
```

State machines (A enforces; B models them read-only):
- **Order:** draft → confirmed → in_production → qc → ready → partly_dispatched → dispatched → closed. Any non-closed → cancelled (owner/manager, with reason; releases reservations).
  `qc` when all production jobs are done and rolls exist pending QC; `ready` when passed length ≥ quantity × (1 − tolerance); `closed` when dispatched and all invoices paid.
- **Job:** planned → ready → running ⇄ paused → done. running/ready/planned → blocked (with reason) → ready. Any not-done → cancelled.
  A job blocked by `machine_breakdown` becomes `ready` either when its machine is repaired or when it is assigned to a different compatible machine (remaining quantity moves with it).
  First-stage job is `ready` once ≥1 yarn issue exists for the order; stage *n* is `ready` when stage *n−1* of the same lot is `done`.
- **Machine:** idle ⇄ running; any → breakdown → idle (repaired); idle → maintenance → idle; idle → changeover → idle; any → offline.
  Exactly one `running` job per machine (DB partial unique index on `jobs(machine_id) WHERE status='running'`).
- **Roll:** pending_qc → passed | rework | rejected; rework → pending_qc (rework complete); passed → dispatched (only via dispatch confirm).
- **Dispatch:** draft → loading → dispatched → in_transit → delivered; draft/loading → cancelled.

## 6. API endpoints

Legend: **Perm** refers to `docs/RBAC.md`. **[idem]** supports Idempotency-Key. **Lane** = who implements. All paths under `/api/v1`.
Prompt 0 creates every router below with full request/response Pydantic schemas and handlers that raise `NotImplementedError` → HTTP 501 (so OpenAPI and frontend types are complete from hour one). Lanes then replace the 501s.

### 6.1 Auth & users (A)

## 7. Domain events

`app.core.events.publish(session, type: str, payload: dict, actor_id: UUID|None)` inserts into `domain_events` **in the caller's transaction** and increments `mill_settings.state_version` for production-relevant types. After commit, an in-process dispatcher (started in `main.py` lifespan) delivers committed, undispatched events to:
1. registered Python handlers (`events.subscribe(type_or_prefix, handler)`) — handlers run in a background thread with their own session; failures are logged and retried up to 3 times;
2. the WebSocket hub (role-filtered broadcast).

| Type | Payload (min.) | Emitter | Consumers |
|---|---|---|---|
| `stock.received` | batch_id, yarn_type_id, qty_g | A | Ripple, WS |
| `stock.issued` / `stock.returned` / `stock.adjusted` | batch_id, job_id?, order_id?, qty_g | A | Ripple, WS |
| `stock.low` | yarn_type_id, available_g, reorder_level_g | A | WS (notifications) |

## 12. Ports, URLs, phones

| Service | Dev URL |
|---|---|

| Postgres | localhost:5432 (user/pass/db = loomlink) |

Phones need **HTTPS** for the camera. In dev: Vite basic-ssl on the LAN IP (accept the warning once) — or a tunnel (`cloudflared tunnel --url https://localhost:5173`). In prod: Caddy with a domain (auto Let's Encrypt) or `tls internal` on the mill LAN.
Vite dev server proxies `/api` and `/api/v1/ws` (ws: true) to the backend so the browser sees one origin (no CORS, cookies work).

## 13. Contract change process

1. Open a GitHub issue titled `CONTRACT: <change>` describing the change and which lanes it affects.
2. The **leader (Lane A)** edits `docs/CONTRACT.md` (and schemas/stubs if needed) on `main` in a single small PR named `contract/<topic>`.
3. Everyone pulls `main`, re-runs `make gen-api`, and adapts.
4. Never change another lane's schemas/routers/types locally "just to make it work".
5. Additive changes (new optional field, new endpoint) are cheap; renames/removals need all three lanes to agree.
